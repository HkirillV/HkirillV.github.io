# Деплой

Сайт — статика. `npm run build` кладёт в `dist/` готовые файлы: пререндеренный
HTML, бандлы, шрифты, картинки, `robots.txt` и `sitemap.xml`. На проде не нужен
ни Node, ни база — только раздача файлов. Поэтому подойдёт любой статический
хостинг, и переезд с одного на другой стоит десять минут.

Живёт на GitHub Pages, бесплатно. Целевой домен — `kirillkhlebov.ru`.

## Как это устроено

Репозиторий называется `HkirillV.github.io` не случайно: репозиторий с именем
`<логин>.github.io` Pages отдаёт в корне, а обычный — по пути `/<репозиторий>/`.
Сайт собран с `base: '/'`, и на корне работают и `hkirillv.github.io`, и будущий
`kirillkhlebov.ru`. Переименуете репозиторий — поедут все пути к ассетам.

Репозиторий публичный, потому что Pages на приватном требует платный Pro.

Деплоит job `deploy` в `.github/workflows/ci.yml`: забирает готовый `dist` из
артефакта job `quality` и отдаёт его в `actions/deploy-pages`. Собирается сайт
один раз, а не заново на каждом шаге.

## Что уже сделано в коде

- `src/shared/config/site.ts` указывает на `https://kirillkhlebov.ru`. Это
  единственный источник правды: из него собираются `robots.txt`, `sitemap.xml`,
  canonical, og-теги и JSON-LD.
- `previews/social/og.html` и перерисованная `public/og.png` — с новым доменом.
- `public/_headers` и `public/.htaccess` — заголовки кэша и безопасности для
  Cloudflare/Netlify и для Apache-хостинга. На Pages оба не работают и лежат на
  случай переезда.
- `scripts/deploy.sh` — заливка `dist/` по rsync на обычный хостинг. Тоже
  запасной путь.

## Шаг 1. Домен

Домен `.ru` стоит 200–300 ₽/год у любого регистратора: timeweb, reg.ru, nic.ru,
beget. Физлицу понадобятся паспортные данные — это требование правил
регистрации домена, а не прихоть регистратора. Бесплатным он не бывает, это
плата координационному центру.

`kirillkhlebov.ru` свободен — проверено у реестра:

```bash
whois -h whois.tcinet.ru kirillkhlebov.ru
```

Если домен успеют занять, разумные запасные: `khlebov.ru`, `kkhlebov.ru`,
`kirill-khlebov.ru`. При смене домена правьте одну строку и перерисовывайте
картинку:

```bash
# 1. поменять url в src/shared/config/site.ts
# 2. поменять подпись в previews/social/og.html
npm run images:render -- og
npm run build
```

## Шаг 2. DNS

У регистратора в DNS-записях домена нужно прописать четыре A-записи на адреса
Pages и одну CNAME для `www`:

| Тип   | Имя   | Значение              |
| ----- | ----- | --------------------- |
| A     | `@`   | `185.199.108.153`     |
| A     | `@`   | `185.199.109.153`     |
| A     | `@`   | `185.199.110.153`     |
| A     | `@`   | `185.199.111.153`     |
| CNAME | `www` | `hkirillv.github.io.` |

Четыре адреса — это не избыточность, а разные точки присутствия: если одна
недоступна, браузер идёт в следующую.

Проверить, что записи разошлись:

```bash
dig +short kirillkhlebov.ru
dig +short www.kirillkhlebov.ru
```

Обычно занимает от четверти часа до пары часов.

## Шаг 3. Домен в Pages

Когда `dig` показывает адреса GitHub:

```bash
echo kirillkhlebov.ru > public/CNAME
git add public/CNAME && git commit -m "chore: point pages at the domain"
git push
```

Файл `CNAME` должен лежать в `public/`, а не в корне: Vite копирует `public/` в
`dist/`, а деплоится именно `dist/`. Положите в корень — он не доедет, и Pages
забудет домен при следующем деплое.

Раньше времени его коммитить не стоит: пока DNS не разошёлся,
`hkirillv.github.io` начнёт редиректить на домен, которого ещё нет.

Дальше в **Settings → Pages** включите **Enforce HTTPS**. Сертификат Let's
Encrypt GitHub выпустит сам, обычно за четверть часа.

## Шаг 4. Проверка

Обязательно — **с мобильного интернета российского оператора**, не с домашнего
вайфая, и попросите пару знакомых открыть.

Заодно посмотрите:

- `kirillkhlebov.ru/robots.txt` и `kirillkhlebov.ru/sitemap.xml` — должны
  отдаваться и содержать правильный домен;
- `http://kirillkhlebov.ru` и `www.kirillkhlebov.ru` — оба должны приводить на
  `https://kirillkhlebov.ru`;
- превью ссылки — вставьте адрес в телеграм или прогоните через opengraph.xyz;
- добавьте сайт в Яндекс.Вебмастер и Google Search Console, скормите им sitemap.

## Чего Pages не умеет

Своих заголовков на Pages не задать: `Cache-Control` он ставит сам, около десяти
минут на всё. Годовой иммутабельный кэш на хешированные бандлы, который описан в
`_headers` и `.htaccess`, там недостижим. На первый заход это не влияет, на
повторные — немного.

Ещё Pages не отдаёт собственные security-заголовки. `X-Content-Type-Options` и
остальные из `.htaccess` на нём просто не появятся.

Если это станет важно — переезд дешёвый, потому что сайт статический.

## План Б: обычный хостинг

Timeweb, Beget, Selectel — около 200 ₽/мес, российские IP, работающий
`.htaccess` со всеми заголовками и никакой зависимости от доступности GitHub.

Порядок: завести хостинг, добавить публичный ключ `~/.ssh/kirillkhlebov_deploy.pub`
в панели, затем

```bash
npm run build

export DEPLOY_HOST=<хост> DEPLOY_USER=<логин>
export DEPLOY_PATH=/home/<логин>/kirillkhlebov.ru/public_html

bash scripts/deploy.sh --dry-run   # посмотреть, что поедет
bash scripts/deploy.sh             # залить
```

`--delete` в скрипте вычищает на сервере то, чего больше нет в `dist/`, поэтому
`DEPLOY_PATH` должен указывать строго на корень сайта.

## Как обновлять сайт дальше

`git push` в `main` — и всё. CI соберёт, прогонит типы, линтеры, 47 юнит-тестов,
e2e с проверкой доступности, Lighthouse и бюджет бандла, а потом выложит.
Красный CI до прода не доходит.
